Update the existing full-stack platform to add a complete rental car management and booking workflow.

Important context:

* The lodging frontend is already built.
* The rental car frontend is already built.
* The admin panel is already built.
* Do not rebuild, replace, or redesign the existing pages unnecessarily.
* Preserve the current UI/UX, authentication, database structure, routing, and existing lodging functions.
* Extend the current system using reusable components and clean database migrations.
* The rental car workflow must work consistently across both the customer-facing frontend and the admin panel.

The initial fleet is:

* 2 Toyota Alphard
* 1 Toyota Sienta

However, the system must allow the admin to add unlimited cars in the future.

# Main Objectives

1. Allow admin users to easily add, edit, duplicate, publish, unpublish, archive, and manage rental cars.
2. Allow admin users to manage each car’s availability through an easy calendar interface.
3. Connect rental car inventory and availability directly to the customer-facing booking flow.
4. Prevent double bookings.
5. Keep booking, payment, customer, vehicle, and availability data synchronized between the frontend and admin panel.
6. Make the full workflow mobile-friendly for both customers and admin users.

# 12. Reservation Creation and Locking

When a customer begins checkout:

* Create a temporary availability hold.
* Hold the selected vehicle for a configurable period, such as 15 minutes.
* Show a countdown during checkout.
* Automatically release the hold if checkout expires.
* Convert the hold into a reservation after successful payment.
* Prevent another customer from reserving the same vehicle during the hold.

Use database transactions or equivalent server-side locking to prevent race conditions and double bookings.

# Definition of Done

The task is complete when:

* Admin can add and edit unlimited rental cars.
* Admin can upload and reorder vehicle photos.
* Admin can publish and unpublish vehicles.
* Admin can manage date-and-time availability from a calendar.
* Maintenance and manual blocks affect frontend availability.
* Customers can search using live availability.
* Unavailable vehicles cannot be booked.
* Temporary checkout holds prevent double booking.
* Customers can complete the full booking and payment flow.
* Reservations appear immediately in admin.
* Admin can manage documents, pickup, return, inspections, and payments.
* Vehicle status updates correctly throughout the rental lifecycle.
* Cancellation releases the vehicle correctly.
* Rental car bookings appear in the customer dashboard.
* Existing lodging pages and admin features continue working.
* The complete workflow works on desktop and mobile.
